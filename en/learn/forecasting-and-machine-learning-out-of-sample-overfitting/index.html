Forecasting and Machine Learning: Out-of-Sample, Overfitting and Baselines

A forecasting model is judged out of sample, not on the training set. Baselines, rolling windows, overfitting and multiple comparisons determine whether it is useful; if a complex model loses to a simple baseline, complexity is a cost rather than an advantage.

Research question

If a forecasting model fits the training set well, does it predict the future? Usually not. This article discusses three tests: whether out-of-sample error beats a baseline, whether the model overfits, and whether comparisons are corrected for multiple testing[1].

Data

Time-series or panel data, forecast target, feature set, train/validation/test split, rolling-window length and missing-value treatment. Time series must not be randomly shuffled, or future information leaks into training; cross-sectional data must also prevent the same entity crossing splits[2].

Method

Forecast error is often measured by RMSE:

RMSE=1n∑(yi−y^i)2RMSE = \sqrt{\frac{1}{n}\sum (y_i - \hat{y}_i)^2}RMSE=n1​∑(yi​−y^​i​)2​

A baseline can be the naive forecast (last value, mean or random walk). A complex model is valuable only if out-of-sample RMSE is consistently below the baseline. Training fits, validation tunes, test reports; the three must not be mixed[3][4].

Results

Suppose baseline RMSE is 10, the complex model has training RMSE 6 and test RMSE 12. Training looks better but out-of-sample is worse, indicating overfitting. If test RMSE is 8, the improvement is 20% versus baseline, but check stability across windows and multiple-testing correction.

Robustness

Change rolling windows, forecast horizons, feature sets and random seeds; check whether the RMSE ranking is stable. A model that wins only in one window may be data mining. Report mean, distribution and worst window, not only average improvement.

Limitations

First, data leakage; second, too-short out-of-sample; third, structural change; fourth, multiple comparisons; fifth, too-weak baseline; sixth, metric not aligned with the decision. Under these conditions, rankings can distort.

Reproduction

Fix data splits and random seeds; report baseline, validation and test RMSE; provide feature lists and tuning ranges; check leakage and multiple comparisons; report worst windows and confidence intervals. The goal is to let readers judge whether the model truly beats the baseline.

Reading and review

An out-of-sample comparison starts by freezing the baseline before discussing model complexity. Set three cases: a last-month mean, a two-variable linear model and a ten-feature model, all trained on the same window, tested on the same holdout and scored with the same loss. If the complex model lowers test RMSE by 5% but lowers training RMSE by 40%, the gap looks more like overfitting than predictive skill. Report a rolling interval: across ten windows, the model should beat the baseline in eight; one win may be a split artefact. Put costs in the decision too: cleaning, monitoring and retraining can cost more than the error reduction is worth.

Reading checklist

One more boundary is easy to miss: the holdout can be reused. If the same test set is used to choose models, tune thresholds and write conclusions, it is no longer a true holdout. Keep a final test set that is opened once, or use rolling windows and log every attempt. Report failed models too; otherwise readers see only survivors.

If the chain cannot be stated without hand-waving, the result is a description, not a usable claim. Run one counterexample and one stress case before extending the conclusion to another market, period or population.

One last check

Finally, keep a model log: date, data version, features, validation split and decision. A result that cannot be reproduced six months later is an anecdote, not evidence.

Column one is where shortcuts appear. Writing "higher is better" is not a definition. At minimum, answer whether the metric is a stock or a flow, whether the denominator is output, population, assets or transaction volume, whether the price is nominal or real, and whether the observation is an endpoint or a period average. Change any one and the ranking or conclusion can move. If a source gives a number without a denominator, return to its footnote rather than borrowing the denominator from a neighbouring article.

Column two turns "Train/validation/test and overfitting" into an observable chain: which variable moves first, through which intermediary, and which outcome changes last. Every link needs a time and a unit; do not mix "long run" with "quarterly". The longer the chain, the more important it is to mark which link is the author's inference and which link has source support. Inference may teach, but it may not masquerade as fact.

Column three handles institutions. Rolling windows and multiple comparisons is not background colour; it is the sample definition. Which entities are covered, which are exempt, when does the rule take effect, and does a cross-border comparison bind the same sample to one rule? Different institutions attach different incentives to the same number. Writing an institutional difference as a behavioural difference is the most common error in cross-market comparison. If the rules cannot be aligned, downgrade the comparison to two separate scenarios and do not rank them.

Column four writes the refutation. End with a falsifiable sentence: "If A is observed and C follows within B, the claim holds; otherwise it fails." A must be observable, B must be a waitable period, and C must be a checkable result. If the three cannot be written, the claim is not testable yet. Keep the worksheet, source links and review date on one page; in the next review, read the four columns before reading the outcome.

Record template

Compress the four columns into one page: measurement and unit on the left, mechanism and institution in the middle, refutation and review date on the right. When data update, change only the numbers and not the conclusion sentence; if the sentence itself must change, the measurement or the institution has changed, so return to the source and redo the check. Keep one column for the opposing view. In the next review, ask whether evidence overturned that view before asking whether the position made money.

A useful record has five fields: the source URL, the access date, the denominator, the rule's effective date and one falsifier. Five fields make the record portable: another reader can reopen the source, recompute the ratio and see which condition would have changed the judgement. A record without them is a diary, not evidence.

Review sentence

Write one sentence only: "Under the ____ convention, a change in ____ affects ____ through ____; if ____ appears, the claim fails." The four blanks are the unit, the variable, the channel and the falsifier. If the sentence cannot be written, at least one of the four columns is still empty; if it can be written but cannot be observed, the falsifier is wrong. On every data update, reread this sentence before reading the charts.

Boundary case: Training RMSE 6, test RMSE 12: the complex model loses to a baseline of 10

A baseline has RMSE 10; a complex model has training RMSE 6 and test RMSE 12. It looks 40% better in training but 20% worse in test, a sign of overfitting. If test RMSE were 8, it would improve 20% on the baseline, but rolling windows still matter: three windows of 7, 9 and 13 average 9.67, only a 3.3% improvement, and unstable. With data leakage, even a test RMSE of 6 can be fake.

The conclusion reverses when out-of-sample improvement is stable and cost is manageable: if the complex model beats the baseline across several holdouts and inference cost is acceptable, it is worth deploying. The boundary is that training error is not model value and the baseline is a gate that must be crossed. Multiple comparisons and leakage turn “improvement” into an illusion.

All numbers are teaching assumptions, not model results.
