Forecasting and Machine Learning

The core of forecasting and machine learning is not model complexity but time boundaries, baselines, validation and drift monitoring.

Problem

Forecasting and machine learning address whether, given historical data and a time boundary, a testable prediction can be made about a future variable and when the model will fail. The core is not model complexity but task definition, baselines, validation and drift monitoring[1][3][4][5].

Inputs

Inputs include the target, forecast horizon (one-step or multi-step), timestamps of available information, feature definitions and update frequency, and the evaluation metric (error, directional accuracy or economic value). If inputs contain data only known in the future, the model is leaking[4].

Assumptions

Assumptions include that historical patterns remain usable for a period, the sample is representative, feature-target relationships are stable and error distributions support evaluation. Time series also assume order matters and cannot be randomly shuffled; structural breaks invalidate historical relationships.

Machine learning additionally assumes train and test are identically distributed; under drift, performance falls. Interpretability methods—feature importance, partial dependence—also carry assumptions and are not causal evidence[2][4].

Steps

Steps fall into four groups: define the task (target, horizon, metric and time boundary); build a naive baseline (last value or historical mean); validate by time (chronological splits, leakage-safe features, model selection and tuning, holdout evaluation); and monitor drift and error after deployment.

Example: train on 2010–2019, validate on 2020–2021, test on 2022–2024; every feature may use only information available at the forecast point. The baseline is “next month's inflation equals this month's”; any model must beat it first[3][4].

Figure

A teaching example: realised inflation in the test period is 2.0%, 2.2% and 2.1%. The naive last-value baseline predicts 1.9%, 2.0% and 2.2%, for MAE=(0.1+0.2+0.1)/3≈0.133 percentage points. A model predicts 2.0%, 2.1% and 2.0%, for MAE=(0+0.1+0.1)/3≈0.067 percentage points, roughly halving the error. If the model only cuts MAE to 0.12 percentage points while raising tail risk, maintenance cost or reducing interpretability, it is not worth replacing the baseline. The numbers are teaching assumptions, not any country’s inflation.

Interpreting results

Interpreting results should report out-of-sample error, its time distribution and directional accuracy, separating statistical significance from economic usefulness. Good test performance does not mean live or policy usefulness; trading costs, decision delays and threshold choices change outcomes[2][3].

Failure conditions

Failure conditions include data leakage (future information in features); random splits of time series; overfitting; repeated use of the test set for tuning; distribution drift and structural breaks; metrics inconsistent with the decision objective. Failure is often a task-definition and validation problem, not an algorithm problem[4][5].

Reproduction

Reproduction requires pinned data versions, feature code, random seeds and hyperparameters; saved train/validation/test splits; baseline comparisons and sensitivity. External validation—different periods or regions—exposes drift better than cross-validation within one sample[1][2][3][5].

Knowledge-point review

prediction tasks

Definition: A prediction task defines the target, horizon, loss function and acceptable errors, including regression, classification, ranking and probabilistic forecasting.

Mechanism: The target drives features, validation and evaluation; regression predicts continuous values, classification categories, probabilistic forecasts distributions, and loss shapes optimisation.

Example: For example, predicting next-month return is regression, default is classification, and default probability is probabilistic.

Boundary: A task is not model choice; target leakage, horizon and loss mismatch optimise the wrong thing, high accuracy may not be economically useful, and targets must fit decisions.

baselines

Definition: A baseline is a simple, transparent, reproducible reference forecast such as historical mean, naive extrapolation, random guess or linear model.

Mechanism: Baselines show whether complex models truly improve; high accuracy without one may reflect an easy task or leakage.

Example: For example, predicting tomorrow's price uses today's price as a baseline, and a complex model must beat it clearly.

Boundary: Baselines are not a formality; weak baselines overstate models, strong ones hide feasible gains, baselines need the same data and metrics, and time-series baselines are essential.

training, validation and test sets

Definition: Training fits the model, validation tunes and selects, and test evaluates once; time series must split by time.

Mechanism: Separation prevents overfitting; cross-validation uses more data, but time series cannot be shuffled randomly or future information leaks.

Example: For example, train on 2010-2018, validate 2019 and test 2020-2022 to avoid future information.

Boundary: Splitting is not mechanical; time leakage, overlapping samples and repeated testing invalidate the test set, repeated validation overfits, and drift makes historical tests unrepresentative.

features

Definition: Features are model inputs or transformations such as returns, valuations, macro indicators, text and interactions.

Mechanism: Feature engineering turns raw data into learnable signals; scaling, encoding, missing handling and selection matter, and features must be available at forecast time.

Example: For example, P/E, momentum and volatility are standardised and imputed as stock-selection features.

Boundary: More features are not better; leakage, collinearity, noise and curse of dimensionality reduce generalisation, importance can be unstable, and domain knowledge beats automatic generation.

interpretability

Definition: Interpretability explains why a model makes a prediction through feature importance, partial dependence, SHAP, rules and surrogates.

Mechanism: Global explanations show overall patterns, local ones single predictions; explanations should be stable, verifiable and consistent with domain mechanisms.

Example: For example, SHAP shows a default prediction driven mainly by leverage and past delinquencies.

Boundary: Interpretability is not causation; importance reflects correlation and scaling, surrogates can distort, explanations can rationalise, and interactions are hard to fully represent.

drift and evaluation

Definition: Drift is change in data distribution, relationships or targets over time, and evaluation uses accuracy, recall, calibration and economic value.

Mechanism: Data, concept and label drift change performance; monitoring, retraining and recalibration sustain it.

Example: For example, a rate regime shift breaks historical default models, requiring recalibration and new features.

Boundary: Evaluation is not one accuracy score; imbalance, asymmetric costs and time change distort metrics, drift detection lags, and retraining can add instability.

Data and institutional check: forecasting

Before using "forecasting" on real data, check four things. First, the unit: is the source reporting a level, a growth rate, an index or a share, and is the denominator output, population, labour force or financial assets? A sentence that changes its denominator can reverse its conclusion. Second, the time convention: nominal and real values, seasonally adjusted and unadjusted series, and fiscal versus calendar years cannot be spliced without a stated base period and conversion method. This matters most when the claim concerns machine learning.

Third, the institutional boundary. out-of-sample testing is defined by a particular legal, supervisory and accounting regime; another regime may not cover the same entities, so a cross-country comparison must first show that one rule binds the same sample. Fourth, run a reverse check: recompute the key ratio from an independent source and confirm at least the order of magnitude, direction and unit before discussing causation.

Boundary conditions and transfer exercises: forecasting

Learning "forecasting" should not stop at a definition. The real exercise is to separate it from "machine learning": the first answers which variable is moving, the second answers through which channel it affects the outcome. They often appear together, but one describes a state and the other a transmission; writing transmission as a state turns correlation into causation. The difference from "out-of-sample testing" is one of level: the first can be observed in a single entity, the latter requires a common rule binding the same sample. Mix the three layers and an article can appear comprehensive while testing nothing.

Transfer practice changes three dimensions, one at a time. Change the entity: from firm to household, from bank to fund; do the numerator and denominator of forecasting still hold? Change the time: from quarterly to annual, from normal to crisis; are the parameters stable? Change the institution: under another regime, does the incentive behind machine learning reverse? If the same mechanism survives all three, the concept is learned; if it collapses on the first change, what was remembered is a case, not a concept.

End with a self-test: explain "forecasting" in 100 words, including one unit, one time convention and one counterexample; then explain in 100 words when "machine learning" fails. If either is missing, return to the module parent and the sibling main article and align definitions and conventions first. Module depth is not word count; it is the ability to give a checkable judgement after changing entity, time and institution.

Exercises

  1. Concept check: explain why time series cannot be split randomly into train and test.
  2. Calculation: state a naive baseline and explain why it must precede a complex model.
  3. Conditions: give one data-leakage example and how to avoid it.
Reference answers
  1. Adjacent observations in a time series are dependent and future values depend on the past; random splitting lets the model see information from before or after the test period and overstates performance. Use chronological blocks and a buffer.
  2. The baseline can be “next month equals this month” or a historical mean; it is the minimum reference and shows whether the model learned signal. A complex model that cannot beat it is not useful.
  3. An example is using revised GDP for the current month to predict the current market reaction when the revision was unavailable at the forecast origin. Avoid it with point-in-time snapshots, availability timestamps on every feature, and a timestamp audit in the pipeline.
  4. Concept check. Explain "forecasting" in no more than three sentences and give a small case where it does not apply.
  5. Mechanism chain. Write the transmission from "forecasting" to "machine learning" in three steps and name the step most dependent on an unstated assumption.
