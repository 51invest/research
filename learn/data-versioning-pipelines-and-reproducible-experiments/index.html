数据版本、管道与复现实验

复现不是把 notebook 再跑一遍，而是固定数据、代码、环境和随机种子，并让每一步都可审计。

模块RES-M12 · 数据工程与复现
层级入门
阅读8 分钟 · 21 节

这篇有一个可以动手操作的演示 ↓

定义

数据版本是对某一时点数据内容和结构的不可变标识，通常用哈希、快照或版本库记录。管道（pipeline）是把摄取、验证、转换、建模和输出串起来的可执行流程；复现实验指用相同输入、代码、环境和随机种子得到相同或可解释的结果。原始数据应只读保存，清洗和派生数据可以重建，结果要带运行记录。

直觉

复现实验像照着菜谱再做一遍同一道菜：食材批次、火候、锅具和操作顺序都要记录，否则味道变了也不知道为什么。数据版本是“食材批次”，代码提交是“火候与步骤”，运行环境是“锅具”，随机种子是“操作顺序”。只保存最终报表，不保存原料和步骤，别人就无法判断结果是配方有效，还是这次恰好成功。可复现不是“再跑一次能出数”，而是“换一个人、换一台机器，按记录能得出同一结论”。

机制

最小管道分五步：摄取时记录来源、时间和校验和；验证时检查 schema、缺失、重复、范围和单位；转换时把每一步写成函数并保存中间表；建模时固定随机种子和超参数；输出时保存结果、日志和环境锁文件。CI 可以在每次提交重跑测试和小样本，数据漂移监控比较分布和关键统计。审计记录要能回答“这份结果由哪份数据、哪版代码、在什么环境下产生”[1][2]。

例子与计算

假设一份月度销售表有 100 万行，原始文件哈希为 A；清洗后删除 2% 重复、补 0.5% 缺失，得到派生表哈希 B；模型输出为 C。若供应商重发了同一月份文件，哈希变为 A'，但行数只多 3 行，校验和会提示变化。若环境从 Python 3.11 升到 3.12，浮点库版本变化可能让结果在小数末位不同；固定 lock 文件可定位差异。若随机种子未固定，交叉验证分数可能波动 0.3 个百分点，不能判断模型是否真的改进。以上为教学示例。

第二个算例：数据版本与指标漂移

假设研究用 2026-09 版数据训练模型，样本 1,000 条，AUC 0.80；2026-10 版新增 100 条，主要是新客户，AUC 降到 0.78。若只看最终报表，会以为模型退化；把数据版本固定后重跑，发现旧版上的 AUC 仍是 0.80，差异来自样本构成，而不是代码。若新增样本中违约率从 5% 升到 8%，而模型阈值不变，召回率会上升、精确率会下降；这不是模型变好或变坏，而是分布变了。记录应包含数据哈希、样本期间、预处理版本、随机种子和评估指标定义；缺少任何一项，0.80 与 0.78 的差异都无法解释。以上为教学假设。

边界与误区

第一，能跑通不等于可复现：没有固定数据和环境，换台机器就可能不同。第二，notebook 的隐藏状态会让“从头运行”与当前输出不一致；应按顺序执行或改用脚本。第三，版本控制只存代码不存大数据时，要单独记录数据快照和校验和。第四，数据许可和隐私限制可能阻止共享原始数据，需提供合成样本或访问控制。第五，复现只证明结果可重算，不证明数据正确或方法有效。

失败模式

第一种失败是用“最新数据”复现旧结果：数据一更新，样本、特征和标签都变了，结果当然不同。第二种失败是依赖 Notebook 的隐藏状态：单元格执行顺序不同，变量被覆盖，重启后结果就变；应把管道写成可从头运行的脚本。第三种失败是随机种子和环境未固定：同一份代码在不同库版本、不同并行度下可能给出不同结果。第四种失败是数据泄漏：预处理时用了未来信息，或训练集与测试集重叠，指标虚高且无法复现。第五种失败是只记录结果、不记录失败：被删掉的异常值、临时改的参数和未采用的模型，都是理解结果的一部分。

三问自检

第一，数据版本是否可用哈希或快照唯一识别，样本期间和预处理是否固定？第二，代码能否从空环境一键重跑，随机种子、依赖版本和并行设置是否记录？第三，评估指标的定义、测试集和基准是否写清，是否检查了数据泄漏？三问都通过，才谈得上“复现”；否则只是“这次跑出来了”。

相邻概念与反例

可复现容易和可重复、可复制混淆。可复现指同一团队用同一数据和代码得到同一结果；可重复指另一团队用新数据或新实验得到一致结论；可复制指独立研究用相同设计得到相同结果。三者的证据强度不同，不能互相替代。反例是“代码能跑就是可复现”：如果数据版本未固定、随机种子未记录、依赖版本漂移，换一台机器结果就会变；能跑一次不等于可复现。另一个反例是“结果相同就是复制成功”：如果两个研究共用同一份有偏数据，结果相同只证明数据一致，不证明结论稳健。比较研究时，应区分数据复现、代码复现和结论复制，并记录失败与偏离。

适用边界

本文的数据版本与可复现框架适用于数据可快照、依赖可锁定、随机种子可记录、且运行环境可容器化的研究。若数据受许可限制不能共享、实验依赖专用硬件，或结果依赖实时市场状态，完全复现可能不可行。它不适用于把代码仓库当作数据版本，也不适用于用一次成功运行证明稳健。使用时先固定数据快照和依赖、再记录种子和环境，并用独立目录重跑；可复现不等于结论可复制。

最后，许可受限的数据应至少保留合成样本和校验和，让外部研究者能复现代码路径。

研究问题

数据版本、流水线和可复现实验要回答的是“同一个研究问题，换一台机器、换一天重跑，能不能得到同一结果”。如果不能，结论就不能当成稳定证据。

数据

需要原始数据、抓取时间、版本号、清洗规则、缺失值处理、样本筛选和许可信息。数据源修订或口径变化必须留下差异记录，不能覆盖旧版本。

方法

把抓取、清洗、特征、建模和评估拆成有输入的步骤；每一步记录参数、随机种子、依赖版本和输出摘要。用内容哈希而不是文件名判断版本。

结果

结果要同时报告点估计、区间、样本量和失败运行；只报成功运行会隐藏选择偏差。复现实验应能在干净环境中从原始数据重跑。

稳健性与局限

换时间窗、换样本、换参数、换随机种子，检查结论方向和量级是否稳定。若结果对合理改动敏感，只能写成条件性结论。

复现检查清单

保留环境锁定文件、数据版本、脚本、参数、随机种子和输出哈希；至少让另一个人或另一台机器按清单重跑一次。
